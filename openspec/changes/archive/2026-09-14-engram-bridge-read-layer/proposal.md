## Why

模型唯一的记忆检索入口在中文上基本不可用：322 条改写查询召回率为 **0**，346 条搜索框式查询里 328 条返回空。已有一条只读派生读层被逐项验证过——召回率 0.78 / 0.95（R@10），检索调用从 207 次降到 51 次。本变更把它工程化进桥。

## What Changes

- 新增检索工具 `mem_bridge_recall`：只读派生，不写记忆、可从正本确定性重算、删除即恢复原状。
- `mem_search` 不再注册。带 `mcp__engram__` 前缀的工具数为 20。
- 默认隔离在项目内，跨项目须显式要求；类型不做枚举，取值无匹配项时给出实际存在的取值。
- 返回条数被截断时模型能看见。
- 正本内容变化后下一次检索即可见；派生数据缺失或损坏时自动重建，其更新要么整体生效要么整体不生效；运行时或模型缺失时在调用点响亮失败。

## Capabilities

### New Capabilities
- `engram-bridge-recall`: 模型可见的记忆检索入口——只读派生、筛选后置、默认项目隔离与显式跨项目、截断可见、内容变化的可见时机、缺失时响亮失败、开关在调用点生效。

### Modified Capabilities
- `engram-bridge-runtime`: 「工具面注册」与「工具面缓存与首个请求可见」的要求改变——刻意不注册的工具从 2 个变为 3 个，且注册面多出一个插件自有工具；另新增「工具面在一次加载内固定」。
- `engram-context-injection`: 新增要求——插件自有工具同样按它自己声明的参数接受注入（含项目注入被关闭时的行为）。

## Impact

- 代码：新增读层（词法索引 + 打分器 + 嵌入运行时 + 常驻进程生命周期）与其工具定义；`src/tools.ts`、`src/config.ts`、`src/index.ts`。新增一个 WASM 依赖，只在子进程内使用。
- 配置（硬规则 5）：引擎开关、数据库路径、索引与模型目录、嵌入线程数、常驻进程空闲回收与扫掠间隔、单次调用超时。
- 规则：非目标改为「不成为记忆的第二个真相来源」，同步 `config.yaml` 的 `context` 与 `AGENTS.md`。原非目标「不做记忆系统本身」写于"检索没问题、缺口只是一个默认参数"的前提之下，该前提已被实测推翻。
- 测试：合成语料单测（增量与全量等价、增量更新的原子性、崩溃与损坏回滚、项目过滤语义、分词一致、批大小约束、宿主入口的边界机制）。
- 文档：`README.md`（安装步骤与工具面变化）；用户侧 `~/.dsh/AGENTS.md` 与 `engram-memory` skill 里的 9 处工具名（**不随插件分发**，只能提供迁移说明）。
- 成本：首次安装约 110 MB；常驻内存随线程数（实测 1 线程 512 MB）；首次全量重建约 12 s。

## 验收信号（可观察）

| 信号 | 观察方式 |
|---|---|
| 工具面 | 模型可见的工具中**没有** `mem_search`、**有** `mem_bridge_recall`，前缀计数为 20；此项**必须插件被重新加载**后才成立 |
| 默认隔离 | 在项目 A 的工作区不指定项目检索，结果里**没有**其他项目的观察 |
| 范围与类型 | 指定范围时只出现该范围；不存在的类型取值会换来实际存在的取值 |
| 截断可见 | 有未显示项时结果说明这一点；提高返回条数后那些项出现 |
| 变化可见 | 写入一条新观察后紧接着检索能看到它，且没有发生全量重建；正本无变化时不重现旧变化 |
| 缺失时响亮失败 | 把模型目录指向空目录，检索返回明确错误、会话仍可继续，且该失败在会话日志里可读 |
| 开关退回 | 关掉引擎开关后，检索调用被以明确原因拒绝，不静默换回另一种检索 |

以下**只记录、不作通过判据**：单次检索耗时、常驻内存的读数、首次重建耗时、模型对提示语的反应。
