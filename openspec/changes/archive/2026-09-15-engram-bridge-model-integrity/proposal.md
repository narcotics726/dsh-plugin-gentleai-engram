## Why

模型与运行时的字节决定了检索所在的**向量空间**。今天没有任何东西断言「检索跑的是验收时那一套」：安装步骤写下的摘要，是**本机刚装下那批字节的现算结果**——换一个 `--model-from` 来源、下载被截断、运行时被换版本，都会生成一份忠实记录新字节的记录，检查于是全部通过。跨机安装因此无法断言两台机器跑的是同一套。派生索引只在向量行里记了一个粗粒度标记（`bge`），**没有任何判定比较过它**。

## What Changes

- 仓库里钉下**期望身份**：检索所需的模型与运行时内容的一份声明，锚在钉死的来源与依赖版本上，且**不随插件配置改变**。
- 安装自证、`--check` 与检索都依据这份声明判定：**不符即失败，而不是照用**；安装记录只描述实际装了什么。
- 失败限于该次检索，且不阻止宿主启动；原因消除后不需要重启宿主即可恢复。
- 派生索引与生成它的模型身份绑定：模型换成另一份时索引重建，不用旧向量作答。
- 安装记录本次实际来源。
- `package.json` 声明所需 Node 版本（`engines`），仅作元数据。

## Capabilities

### New Capabilities

- `engram-bridge-model-install`: 模型与运行时的期望身份（仓库侧声明）、安装后自证、内容校验与来源记录——安装侧的可断言性。

### Modified Capabilities

- `engram-bridge-recall`: 「运行时或模型缺失时响亮失败」扩展为「不可用」（内容与声明的期望身份不符也须响亮失败，失败限于该次检索）；新增「派生索引与生成它的模型身份绑定」。

## Impact

- 代码：新增仓库侧期望身份模块；`src/recall/model-dir.ts`、`src/recall/process.ts`、`src/recall/worker.ts`、`src/recall/index-db.ts`（索引记模型身份）的判定与失败路径；`scripts/install-recall-model.mjs`（含复制语义修正）；`package.json` 的 `engines` 与 `openspec/config.yaml` 的 Node 基线。
- 测试：夹具需注入一份匹配的测试期望（合成字节不可能等于真实摘要）；新增判定、失败作用域、自愈、索引身份的单测；更新两处既有消息断言。
- 文档：`README.md` 的显式安装一节；`AGENTS.md` 的安装命令说明。
- 成本：判定读约 110 MB，实测约 48–52 ms（见 `design.md` D12），只在启动检索子进程的那一次发生（热调用不变）。**另有一次性的**：既有派生索引缺新记录的模型身份，升级后第一次检索会触发一次全量重建（归档读数：**346 条量级 ≈11.96 s @16 线程**）——它同时把"旧索引被静默复用"这条故障修掉，故判定为值得。

## 验收信号（可观察）

| 信号 | 观察方式 |
|---|---|
| 期望身份在仓库 | 仓库里能读到所需内容的期望身份与所锚定的来源；运行时那部分可由锁定版本的依赖**离线重算**并逐条一致 |
| 安装自证 | 安装完成时依据期望身份判定；把来源换成一份不符的字节时非零退出并指名内容 |
| 内容不符被抓住 | 把已安装文件改动一个字节后 `--check` 非零退出，输出里指名该文件与期望/实际 |
| 来源可追溯 | 安装记录里能看到本次的实际来源（远端或本地） |
| 失败作用域 | 用不符的内容检索：该次失败，而宿主进程未退出、pid 不变、会话继续、工具面不变 |
| 不阻止启动 | 在内容不符的状态下冷启动宿主：宿主启动成功、工具面完整，首次检索以明确错误失败 |
| 自愈 | 原因消除后，紧接着的下一次检索恢复，无需重启宿主 |
| 索引与模型同代 | 模型换成另一份后，索引重建，而不是用旧模型的向量作答 |

以下**只记录、不作通过判据**：判定耗时；`--check` 的逐字措辞（其内容要件见 delta spec）。
