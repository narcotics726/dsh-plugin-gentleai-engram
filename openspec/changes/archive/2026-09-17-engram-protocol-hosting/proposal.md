## Why

engram 的触发条件与完整流程今天是两台机器上的手抄件：插件的版本与它们之间没有任何约束——改插件不动文本，改文本不随插件分发，两台机器各自漂移。模型面还缺一条上游有、而我们只写给自己人看的规则：记忆工作是账务，不是用户可见的回答。

## What Changes

- 常驻触发条件与完整流程改由插件自带并注入：前者进系统提示词，后者作为插件自带的运行时技能；用户家目录不再需要任何 engram 文本。
- **BREAKING**（模型面）：每个请求的系统提示词新增一段常驻文本，推翻「不新增 system prompt 段」这条既有约束。段是静态的，代价一次性；有义务却没有办法执行它的子 agent 拿到空段。
- 文本的唯一真相在插件里，随插件版本分发：改文本下一次请求即生效，删掉手抄件不改变模型看到的内容。
- 顺手补齐对话规则：记忆工作先做完再作答、失败也要作答；把「判无冲突不落库」的理由换成站得住的那些；清掉技能里指向手抄件文件的悬空引用。

## Capabilities

### New Capabilities

- `engram-protocol`: 模型在任何会话里被告知的 engram 义务——触发条件常驻、流程按需加载、文本随插件版本分发、可见范围与这套工具一致。

### Modified Capabilities

（无：既有 64 条需求里没有第二条涉及「模型被告知了什么」。新增需求把「与工具可见范围一致」写成插件自己维持的不变量，因此不需要在 `engram-bridge-runtime` 的「子 agent 遮蔽」上留改动。）

## 验收信号（可观察）

| 信号 | 观察方式 |
|---|---|
| 常驻段进了系统提示词 | 真实会话的 `system/message` 事件里出现该段文本，且**只出现一次**（`request/header` 在本机**没有** `system` 字段，不能用作判据） |
| 子 agent 不承担 | 同一轮里子会话的 `system/message` 不含该段 |
| 流程按需加载 | 会话技能目录里出现该技能且来源为 `runtime`（插件自带）；未加载时正文不在提示词里 |
| 文本唯一真相在插件 | 删掉两台机器上的手抄件后，模型看到的内容与删除前逐字节一致 |
| 改文本即生效 | 改插件里的文本并重新构建、重新加载后，下一次请求的 `system/message` 里该段随之改变 |
| 停用即消失 | 停用插件后，该段从系统提示词消失、技能目录里不再有它，且配置转储无残留 |
| 段内容与次序恒定 | 探针读回组装出的段序列两次（不同 step）：该段正文逐字节相同、`name` 与 `order` 不变，且仍夹在 persona 段之后、第一方政策段之前。**不要**断言「整个提示词逐字节相同」——相邻的 plan 政策段由模型自己切换的 plan 模式决定 |
| 搬运是搬运 | 搬运步骤里（内容修订之前），插件内文本与两台机器手抄件逐字一致 |

## Impact

- 代码：新增协议文本的加载与 frontmatter 拆分模块、`src/index.ts` 里两条可选注入（`systemPrompt` / `skills`）各自包在 `ctx.effect` 里；新增随包的资产目录；`package.json` 的 `files` 与两个开发依赖（`@deepseek-ai/dsh-system-prompt`、`@deepseek-ai/dsh-skill`，仅类型）。
- 测试：文本缺失在加载点抛出、frontmatter 拆分（含无 frontmatter 的常驻段）、子 agent 返空判定、注册字段齐备（`source` 必填）、注册与卸载的计数。
- 探针：`scripts/probe/probe-events.mjs` 现在**不含** `system/message`，全文也没有读 `header.system` 的地方——段位与「只出现一次」两条判据都要先给它加这一项。
- 文档：`README.md`「模型看到什么」一节；`openspec/config.yaml` 的 context 删掉那条约束；`docs/engram-upgrade-checklist.md` §5 **顺手修掉第 2 条那条已失效的判据**（它读 `request/header.data.header.system`），并新增段位指纹一条。
- 用户侧文件：两台机器的 `~/.dsh/AGENTS.md`（删该行）与 `~/.agents/skills/engram-memory/`（删目录）。插件**不会**因此报错（同名时插件自带的那份按层内次序胜出），宿主日志里只会留一条 warn——因此删除与验证都写成任务。
- 成本：系统提示词净增一段常驻文本（字节数在 design 记为实测值）；技能目录多一条摘要（上限 500 字符）。派生索引、工具面、会话事件一律不变。
