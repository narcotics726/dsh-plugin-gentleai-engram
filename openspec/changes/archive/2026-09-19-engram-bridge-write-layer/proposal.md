## Why

模型唯一的记忆写入入口在中文上基本失效：它的冲突候选只拿**标题**走 FTS5，而本机 engram 的 FTS 建表未指定分词器，中文只在标点处切开。判据：动工前的一次保存返回 3 个候选，得分贴在最不相关的一端（`-2e-6`，默认地板 `-2.0`），且它们靠标题里的 ASCII 命中、中文没有参与；而每次写入仍为这些空候选插入 pending 关系行。入口脏时在出口过滤没用——这条已由读层的结论确立。

## What Changes

- 新增桥自有的保存入口，经 engram 的 HTTP 写入面写入；上游写入工具不再注册，模型可见的工具面数量不变。
- 保存结果带上真实候选：由读层的派生数据算出（语义向量召回 + 词法重排），并给出足以让调用方裁决的机械证据。
- 候选只在那一次保存的回合内有效：插件不重发、不恢复、不补发，也不让候选影响后续调用。
- 裁决经 engram 自身的关系记录路径落库；撤销对**同回合写下的**关系是两步可达的（见 design D7），旧关系的撤销需要读层露出关系标识，留给读层那个变更。
- HTTP 写入面不可达时回退到上游写入工具；归因靠结果文本与日志（来源标记只是旁证）。
- 候选永不牵连写入：预算短、失败静默降级、不追尚未进索引的变化。
- 常驻触发段与技能正文改写（保存工具名、候选时效、裁决路径）。

## Capabilities

### New Capabilities
- `engram-bridge-save`: 桥自有保存入口——写入不依赖候选、候选随结果交付且当回合过期、裁决落 engram 的关系记录、写入面不可达时回退且可辨、不追尚未进索引的变化、受检索引擎开关约束、归属与拒绝条件。

### Modified Capabilities
- `engram-bridge-runtime`: 「工具面注册」中刻意不注册的那组多一类（被桥自有保存入口取代的写入工具），插件自有工具由 2 个变 3 个。
- `engram-session-binding`: 「会话标识注入」把判据主体写到保存入口上——它与其他工具走**同一套**注入（声明了就注入、显式传值优先）；注入关闭且未显式传值时，由保存入口自己的规格以明确原因拒绝，而不是自带一个值继续写。
- `engram-protocol`: 新增「文本里要求模型调用的记忆工具都在场」（对「刻意不注册」的提及与「要求调用」区分开）。

## Impact

- 代码：新增保存入口（HTTP 写入客户端 + 工具定义）、候选查询（worker 新命令，复用既有打分与索引）、工具面清单、注入与回退路径；`src/tools.ts`、`src/index.ts`、`src/recall-tool.ts`（同构先例）、`src/recall/protocol.ts`、`src/config.ts`、`protocol/*.md`。
- 配置（硬规则 5）：候选查询的预算与开关联动、回退与留痕相关键；改动后不需要重启宿主。
- 依赖：只用 Node 内置能力（宿主进程内不加载任何原生扩展），不新增第三方包。
- 环境前提：写入走 engram 的 HTTP 面，因此需要那个服务在跑（`engram serve`，默认端口）；插件**不负责发现或启动它**（它同时承载云同步，不该由插件代管）。缺失时保存回退，并在日志与结果文本里说明——文档要写明这条前提。
- 测试：HTTP 写入通道的桩与逐项对照（FTS 触发器 / 去重 / topic_key 升版 / review_after / 同步入队 / session 归属）、工具面数量、回退可辨、候选预算与静默降级、不追新、协议文本指名的工具都在场。
- 文档：`docs/engram-upgrade-checklist.md`（补 HTTP 写入面与「`/health` 不能作版本特征检测」两条复测项）、`README.md` 工具面一节。
- 成本：保存路径多一次常驻进程往返（温进程数十毫秒）；冷进程是模型加载，由短预算截断并降级为无候选。

## 验收信号（可观察）

| 信号 | 观察方式 |
|---|---|
| 工具面 | 模型可见的工具中**没有** `mem_save`、**有** `mem_bridge_save`，前缀计数与变更前相同；此项**需插件被重新加载**后才成立 |
| 无垃圾候选行 | **写入面可用时**：经新入口保存一条中文记忆后，`memory_relations` **不新增** `pending` 行；同一操作走上游路径时会新增（对照）。回退路径可能新增，但它**不得**把上游候选转述给模型 |
| 候选随保存交付 | 保存一条与既有记忆近似重复的中文条目，结果里出现那条既有记忆（含条目标识、本次落库条目的标识与机械证据） |
| 候选当回合过期 | 插件**不再重发**候选、也不让它们影响后续调用；诊断计数只存在于会话内存、不落盘；模型若要跨回合使用，只能引用对话里已经出现过的编号 |
| 写入不依赖候选 | 把模型目录指向空目录后保存：写入成功、结果里没有候选、会话继续 |
| 不追索引 | 索引落后于正本时保存：仍以当前索引作答，没有触发追新或重建 |
| 回退可辨 | 令写入面**连接被拒**：保存仍成功，该行没有来源标记，结果文本与日志各留一条回退记录。来源标记不是充分证据（响应超时可能已提交且带标记），判据是结果文本 + 日志。**4xx 时相反：不回退，以明确原因失败** |
| 开关 | 检索引擎开关关闭后，保存照常成功、不产出候选；会话或项目注入开关关闭且未显式传值时，保存**以明确原因被拒绝**（项目那一支是刻意引入的行为变化，见 design D14） |
| 协议一致 | 文本里**要求模型调用**的每个记忆工具都在工具面上；对「刻意不注册」的提及被显式标注为不可调用 |
