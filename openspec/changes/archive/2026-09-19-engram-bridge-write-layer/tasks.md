## 2. 保存通道（W1）

- [x] 2.1 实现 HTTP 写入客户端（宿主进程内，只用 Node 内置 `fetch`）：把工具入参映射成写入接口的 body（`session_id` / `type` / `title` / `content` / `project` / `scope` / `topic_key` / 来源标记）与返回解析。**归一化由桥在两条路径之前统一做**：缺省 `type` 补成与上游 MCP handler 相同的值、`observation` 别名映射到 `content`——两条路径发出的内容必须逐字相同。
  - 验证：单测用本地 stub HTTP server 断言 body **逐字段**正确（含来源标记与归一化结果）；构造「省略 type / 使用 observation 别名」两种入参，断言两条路径产出的 body 逐字相同；错误分类覆盖连接被拒 / 连接或读超时 / 5xx / 4xx 四类；**断言调用给的取消信号被传进写入请求**（宿主的截止是协作式的，不传等于超时形同虚设：中止信号后请求被放弃）。

- [x] 2.2 回退：触发集 = 连接被拒、连接或读超时、5xx；**4xx 不回退**，以明确原因失败且不落库。回退走上游写入工具（桥内部调用，不经工具面），**受它自己的独立预算约束**（不继承共享的 `toolCallTimeoutMs`；客户端没有 per-call 超时，实现要自己合成 deadline），超预算即如实失败。在日志与结果文本各留一条可归因记录；**结果里不转述上游返回的候选与判定标识**（本插件自己的候选照常给出），并**从上游信封里解析出「本次落库标识」**以履行与新路径同样的结果义务。**不做冷却**（本机连接被拒是毫秒级；挂住的进程由写入超时兜住），因此「服务可达」时一定走写入面。
  - 验证：单测四类错误各一条——连接被拒 ⇒ 保存成功、结果含回退字样与**本次落库标识**、日志一条、结果里**不出现**上游候选字段；4xx ⇒ 保存失败且无落库；5xx ⇒ 回退；**回退超预算 ⇒ 如实失败且结果里没有"已保存"措辞**；断言回退响应里出现了待判行（由 `judgment_required` / 候选非空推断）时**日志记下该事实**、结果里**不出现**它们；断言回退调用**不**受共享 `toolCallTimeoutMs` 约束（把共享键调得极小，回退仍按其独立预算工作）；断言不存在任何"跳过写入面"的状态。

- [x] 2.3 对照实验：同一批入参分别走两条路径落进**隔离库**，逐项比对（FTS 触发器 / 去重 / `topic_key` 升版 / `review_after` / 同步入队 / session 归属 / 来源标记），并断言经写入面路径落库后 `memory_relations` **零增量**，而回退路径**可能**新增（对照）。
  - 验证：一次性脚本（隔离 `HOME`）跑两路径并 diff 两行记录；两条路径的 `memory_relations` 增量分别断言；脚本本身不入库（读数写进 design 的「验收读数」一节）。

- [x] 2.4 保存工具定义：参数面与上游保存工具对齐（`title` / `type` / `scope` / `topic_key` / `content` ＋ 既有的 `observation` 别名），**去掉**上游特有的 `capture_prompt` / `project_choice_reason` / `recovery_token`，并**声明** `session_id` 与 `project`（与 recall 工具同形：声明了就按既有注入取得，调用方显式传值优先）；把上游保存工具加入刻意不注册清单。
  - 验证：单测断言工具名在场、上游保存工具**不在**工具清单、以它的名字调用得到未知工具错误、新工具参数 schema 与设计一致（**断言 schema 里含 `session_id` / `project`**）；前缀计数与变更前相同（21）；`pnpm check:boundary` 通过。

- [x] 2.5 归属按既有注入取得，不新增机制：注入打开时请求携带该会话已解析出的会话标识与项目；显式传值优先；**任一注入关闭且调用方未显式传值时，以明确原因拒绝**（形状与 recall 在同样情形下的拒绝一致：说明缺哪个值、有哪两条出路），不落库、不静默改用别的值。
  - 验证：单测对四种开关组合各跑一次保存，断言「都打开 ⇒ 成功且带两个值」「任一并闭且未显式传 ⇒ 明确拒绝且无落库」「显式传值 ⇒ 不被改写」；断言拒绝文本里含缺口与两条出路；断言请求字段的来源与 recall 走的是**同一个**注入实现（不是第二套取值代码）。

- [x] 2.6 拿不到会话项目时以明确原因拒绝且不落库（并入 2.5 的四组合验证；这里单独留一条是为了覆盖「后端没给出项目」这一支）。
  - 验证：单测构造「会话项目未解析」情形；隔离库断言无新行。

- [x] 2.7 自反对防御：桥在转关系写入之前拒绝两个标识相同的请求。
  - 验证：单测断言 `a == b` 的调用被拒且关系记录零增量（上游对自反对没有保护，这一层防御是必须的）。

## 3. 候选查询（W2）

- [x] 3.1 常驻进程新增一条候选查询命令，契约与检索**刻意相反**：按当前派生状态作答、不追新、不触发重建、超时即放弃、运行时或模型缺失时静默返回空；并**限定在同一项目**内（跨项目的对在本后端写不成关系）。
  - 验证：单测断言五条——① 正本有新变化时该命令**不做**同步（索引字节不变）；② 索引缺失/不可信时返回空而不是重建；③ 超预算时返回空且保存照常；④ 模型目录指向空目录时返回空而**不**抛错（与检索的响亮失败形成对照断言）；⑤ 其他项目的相似条目不出现在结果里；并断言该命令**接受取消信号**（读层现在的入口 `query()` 不接信号、只有底层调用接，候选查询要顺手接上）。

- [x] 3.2 候选排序复用读层自己的打分器（`Scorer`），`B` 取读层检索的既有键、`M` 取新键，断言 `B ≥ M`；候选在**写入之前**算出。
  - 验证：单测断言排序调用与检索走同一个打分器（改动打分器常量时候选顺序随之变化）；断言 `B < M` 被拒；断言候选计算发生在写入之前（stub 记录调用顺序）；断言升版/去重那一支的标注是**写后按返回标识比对**得出的（构造命中 `topic_key` 与命中内容去重各一次，并构造一次「目标不在候选集里」——此时不出现该标注、也不声称是新增）。

- [x] 3.3 证据：候选的**规范值就是结构**（`id` / `title` / `type` / `updated_at` / `same_topic_key` / `same_session` / `same_type_and_title` / `identical_content` / `shared_rare_terms{count,terms}` / `semantic_rank` / `corpus_size` / `will_update`），模型看到的是它的**投影**（紧凑标签行）。有界回读正本**在常驻进程里**做（只读句柄、一条 `IN (...)`、条数上限 = 展示条数）取 `topic_key` / `session_id`——`normalized_hash` 在规范结构里没有落点，去重那一支已由「写后按返回标识比对」承担（见 design D12 的偏差注记）。
  - 验证：单测断言结构字段齐备且**中性命名的字段名不变**（`same_type_and_title`，不得出现 `template_like` 之类把判断写进名字的字段）；断言含 `will_update` 而**不含**依赖「新行已存在」的字段（如 `earlier`）；断言投影与结构同源（改结构字段 ⇒ 投影随变）；断言共享词**列出词本身**而不只给计数；断言渲染里**不出现**任何内部排序分数或相似度原始值；断言正本读取带 `IN` 且条数有上限。

- [x] 3.4 候选只在本次保存的结果里出现：不使用任何跨回合存储（不落库、不写自有待办清单）。结果里同时给出**本次落库条目的标识**，使方向无歧义。
  - 验证：单测断言保存前后派生数据与正本逐行不变（除那一条新记忆）；断言结果里两个标识都能被区分（本次的 / 候选的）；构造两次保存，断言第二次的候选由当时内容重算。

- [x] 3.5 有候选时在结果末尾附一句固定的**动作提醒**：先读候选全文；没把握就不要记录；要问使用者就在**本次回复里**问并**把两个标识都写进问题**（本次保存的那条与候选那条），并说明**候选不会重发**。没有候选时不出现；措辞是常量且被测试钉住。
  - 验证：单测断言有候选时该句出现、无候选时不出现、措辞与常量逐字相等；断言该句**不含**任何关系结论词（例如「重复」「取代」「冲突」）；断言该句含「本次回复」「不会重发」与**两个标识**三处动作约束；`grep` 确认判法正文仍只在协议资产里有一处。

- [x] 3.6 裁决路径的实测：对两个条目下判「有真实关系」会在关系记录里写出 judged 行；同一对再判是**改写**而非新增；判「无关」**不写任何行且该次调用不返回新的关系标识**；同回合内用返回的标识两步撤销能生效。
  - 验证：隔离库脚本四步走（写关系 / 重判 / 判无关 / 两步撤销），每步断言关系表的行数与状态，并对「判无关」那一步断言**零增量**且返回里没有新的关系标识；结果写进 design 的「验收读数」。
